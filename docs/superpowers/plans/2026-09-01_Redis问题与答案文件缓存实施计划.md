# Redis 问题—答案文件缓存实施计划

> 日期：2026-09-01  
> 状态：已实施（待真实 Redis 端到端验收）  
> 适用范围：首页预设问题、热门问题、普通智能问答、FastAPI 流式与非流式聊天接口  
> 核心目标：以用户问题原文作为 Redis 缓存键，以答案文件路径作为 Redis 值；命中后读取答案文件并直接返回，未命中时执行现有问答流程，将最终回答写入文件并回填 Redis。

> 当前进度：Task 1～5 已完成；缓存单元测试、聊天接口缓存测试和原有聊天流式测试通过。全量后端测试为 179 通过、1 个既有 RAG golden case 失败（证据评估断言，与本次缓存改动无关）。Task 6 的真实 Redis 验收需在 Redis 服务可连接后执行。

## 1. 已确认的设计决策

本项目用于比赛演示，优先保证实现简单、效果直观和缓存加速可展示，不扩展为生产级语义缓存系统。

采用以下固定设计：

```text
Redis Key   = qa:answer-file:{问题原文}
Redis Value = 相对于答案根目录的文件路径
答案正文     = 文件中的完整文本
```

示例：

```text
Key:
qa:answer-file:我是本科生，请介绍适合学生使用的校园服务和资料入口

Value:
preset/student.md
```

缓存命中后，后端在配置限定的答案目录中读取：

```text
data/qa_answers/preset/student.md
```

Redis 不直接保存回答正文。预设回答和运行时生成的回答都以文件为唯一正文载体。

## 2. 实施目标与非目标

### 2.1 实施目标

1. 首页四个角色入口和六个热门问题可以在应用启动时预热到 Redis。
2. Redis 命中时跳过 Query Planner、RAG、工具调用和大模型生成。
3. 普通用户问题首次未命中时走现有问答链路，回答完成后写入答案文件并建立 Redis 映射。
4. 当前前端继续调用 `/api/chat/stream`，不需要修改请求协议。
5. 同时兼容 `/api/chat` 非流式接口。
6. Redis 无法连接、映射文件不存在或答案文件读取失败时，自动退回原问答流程。
7. Redis 连接信息先提供本地占位配置，后续可直接替换为真实地址和密码。
8. 日志可以明确展示 `HIT`、`MISS`、`WRITE` 和 `BYPASS`，方便比赛现场演示。

### 2.2 非目标

- 不实现语义相似问题匹配。
- 不处理标点、同义词、空格和大小写归一化；除现有请求入口的 `trim()` 外按问题原文精确匹配。
- 不按历史对话、用户、角色或资料模式拆分缓存。
- 不实现 Redis 集群、哨兵、分布式锁或缓存击穿治理。
- 不提供缓存管理后台。
- 不要求缓存命中后重新执行检索或重新生成来源。
- 不把答案文件存入 Redis，也不让 Redis Value 接受客户端提供的任意路径。

## 4. 配置设计

### 4.1 Python 配置项

在 `backend/config.py` 的 `Settings` 中增加：

```python
redis_url: str
qa_cache_enabled: bool
qa_cache_prefix: str
qa_cache_ttl_seconds: int
qa_answer_dir: Path
qa_preset_manifest: Path
```

建议默认值：

```text
REDIS_URL=redis://127.0.0.1:6379/0
QA_CACHE_ENABLED=true
QA_CACHE_PREFIX=qa:answer-file:
QA_CACHE_TTL_SECONDS=0
QA_ANSWER_DIR=data/qa_answers
QA_PRESET_MANIFEST=data/qa_answers/presets.json
```

说明：

- `REDIS_URL` 当前先使用本机无密码地址，后续可以整体替换为真实连接串。
- `QA_CACHE_TTL_SECONDS=0` 表示演示阶段不主动过期；后续设置为正整数时使用 `SETEX`。
- `QA_ANSWER_DIR` 和 `QA_PRESET_MANIFEST` 的相对路径必须以项目根目录为基准解析。
- 密码不写入仓库，只写在本地 `.env`；`.env.example` 仅保留占位格式。

### 4.2 Redis Value 约束

Redis Value 只保存相对路径，例如：

```text
preset/student.md
generated/7dd58f1f....md
```

不保存绝对路径，以免项目目录变化后全部失效。读取时统一通过：

```python
resolved = (settings.qa_answer_dir / relative_path).resolve()
```

并校验 `resolved` 仍位于 `QA_ANSWER_DIR` 内，防止读取答案目录之外的文件。

## 5. 预设问题与答案文件

### 5.1 清单格式

`data/qa_answers/presets.json` 使用简单对象：

```json
{
  "我是本科生，请介绍适合学生使用的校园服务和资料入口": "preset/student.md",
  "我是研究生，请介绍研究生培养、学位和资料下载入口": "preset/graduate.md",
  "我是教师，请介绍教学、科研和办公相关的校园服务入口": "preset/teacher.md",
  "我是考生或家长，请介绍学校概况、学院专业和招生信息": "preset/applicant.md"
}
```

正式实施时将首页 `roleEntries` 和 `POPULAR_QS` 中的全部固定问题纳入清单，确保字符串逐字一致。

### 5.2 答案格式

答案文件统一使用 UTF-8 Markdown：

```markdown
## 本科生常用校园服务

这里是完整回答正文……
```

文件中只保存最终展示文本，不包含 SSE 协议、Redis Key 或本机绝对路径。

### 5.3 启动预热

FastAPI `lifespan` 启动阶段执行：

```text
创建 Redis 客户端
→ PING Redis
→ 读取 presets.json
→ 校验每个答案文件存在且位于答案根目录
→ SET 问题到相对文件路径的映射
→ 记录成功、跳过和失败数量
```

预热只写映射，不把 Markdown 正文写入 Redis。单个预设文件错误只跳过该项，不中止应用启动。

## 6. 缓存服务设计

`backend/cache/qa_file_cache.py` 负责所有 Redis 与文件操作，API 层不直接拼 Redis 命令或磁盘路径。

建议接口：

```python
class QAFileCache:
    async def connect(self) -> None: ...
    async def close(self) -> None: ...
    async def warmup_presets(self) -> WarmupResult: ...
    async def get_answer(self, question: str) -> CachedAnswer | None: ...
    async def save_generated_answer(self, question: str, answer: str) -> str | None: ...
```

返回对象至少包含：

```python
@dataclass
class CachedAnswer:
    answer: str
    relative_path: str
    kind: Literal["preset", "generated"]
```

### 6.1 查询流程

```text
question.strip()
→ 拼接 Redis Key
→ GET 相对文件路径
→ 路径安全校验
→ 在线程中读取 UTF-8 文件
→ 返回文件正文
```

以下情况统一视为缓存未命中并回退：

- Redis 未启用或未连接；
- Key 不存在；
- Value 为空或不是合法相对路径；
- 文件不存在；
- 文件不在答案根目录；
- 文件无法读取或正文为空。

Redis 中存在映射但文件不存在时，异步删除该失效 Key，避免之后重复读取失败。

### 6.2 运行时回答落盘

动态回答文件名使用问题原文的 SHA-256：

```text
generated/{sha256(question)}.md
```

写入顺序：

```text
将完整回答写入同目录临时文件
→ 原子替换为最终 Markdown 文件
→ Redis SET 问题到相对路径的映射
```

必须先成功写完文件，再写 Redis，避免 Redis 指向半成品或不存在的文件。

相同问题生成相同文件名，重复写入时覆盖该问题旧回答。文件写入使用 `asyncio.to_thread()`，避免阻塞 FastAPI 事件循环。

## 7. 聊天接口接入

缓存判断放在 `backend/api/chat.py`，位置在身份与资料范围合法性校验之后、创建并调用 `AgentController` 之前。

这样既保留现有请求校验，又能在命中时完整跳过昂贵问答链路。

### 7.1 流式 `/api/chat/stream`

目标流程：

```text
请求进入
→ 完成现有权限校验
→ qa_cache.get_answer(req.question)
   ├─ 命中：返回 meta + token + done
   └─ 未命中：继续 controller.handle_stream()
                → 原样转发 SSE
                → 同时累计 token 文本
                → 正常收到 done 后落盘并回填 Redis
```

缓存命中时发送兼容现有前端的 SSE：

```text
data: {"type":"meta","confidence":"high","sources":[],"attachments":[],"tools_used":["redis_file_cache"],"fallback":false,"cache_hit":true}

data: {"type":"token","content":"答案文件的完整正文"}

data: {"type":"done"}

```

第一版一次发送完整正文，不模拟逐字输出。前端现有 `token` 处理逻辑可以直接显示。

缓存未命中时，在包装现有 SSE 的过程中只累计 `type=token` 的 `content`；只有满足以下条件才写缓存：

1. 收到了正常 `done`；
2. 最终正文非空；
3. 请求没有被取消；
4. 没有进入“回答生成失败”异常分支；
5. 不是无依据兜底回答。

无论缓存写入成功与否，已经生成的 SSE 都继续正常返回前端，缓存不得改变主链路结果。

### 7.2 非流式 `/api/chat`

目标流程：

```text
缓存命中
→ 用文件正文构造 ChatResponse

缓存未命中
→ controller.handle()
→ 返回原结果
→ 若回答有效则异步写答案文件并回填 Redis
```

命中时使用固定元数据：

```json
{
  "confidence": "high",
  "sources": [],
  "attachments": [],
  "tools_used": ["redis_file_cache"],
  "fallback": false
}
```

本期只缓存回答正文，因此命中后不恢复首次生成时的来源、附件或检索摘要。回答文件正文中可以直接保留需要展示的 Markdown 链接。

## 8. 生命周期与降级行为

在 `backend/app.py` 的 `lifespan` 中：

### 启动阶段

1. 创建全局 `QAFileCache` 实例。
2. Redis `PING` 成功后标记 `qa_cache_status=ready`。
3. 执行预设问题预热。
4. Redis 失败时标记 `qa_cache_status=unavailable`，记录错误类型，但继续完成 FastAPI 启动。

### 关闭阶段

1. 关闭 Redis 客户端。
2. 不删除答案文件和 Redis 数据。

可以在 `/health` 增加非敏感状态：

```json
{
  "qa_cache_status": "ready"
}
```

状态限定为 `disabled`、`ready`、`unavailable`，不返回 Redis URL、密码或本机路径。

## 9. 日志与演示可观测性

日志只记录必要信息，不输出完整问题和完整答案：

```text
qa_cache event=hit key_hash=... kind=preset duration_ms=...
qa_cache event=miss key_hash=... duration_ms=...
qa_cache event=write key_hash=... kind=generated duration_ms=...
qa_cache event=bypass reason=redis_unavailable
qa_cache event=stale_mapping key_hash=...
```

比赛演示时可以通过日志说明：

1. 第一次普通提问显示 `MISS`，走 RAG/大模型；
2. 回答完成显示 `WRITE`；
3. 第二次发送完全相同问题显示 `HIT`，立即返回文件内容；
4. 首页预设问题第一次点击即显示 `HIT`。

## 11. 测试清单

### 单元测试

- Key 使用固定前缀加 `question.strip()`。
- Redis 命中且文件存在时返回正文。
- Redis 未命中时返回 `None`。
- Redis Value 不是路径或越出根目录时拒绝读取。
- 映射存在但文件缺失时删除失效映射。
- 保存动态答案时文件先落盘、Redis 后写入。
- Redis 写入失败时保留已生成回答，不影响当前请求。
- TTL 为 0 使用普通 `SET`，TTL 大于 0 使用带过期时间的写入。

### API 测试

- 流式命中事件顺序为 `meta → token → done`。
- 流式命中不调用 Controller。
- 流式未命中完整转发原 SSE。
- 流式正常完成后缓存最终 token 拼接结果。
- 流式异常、取消、空回答和 fallback 不缓存。
- 非流式命中返回完整响应模型。
- Redis 不可用时两个接口均回退到原实现。

### 前端回归

- 首页角色入口仍自动发起问题。
- 首页热门问题仍自动发起问题。
- 缓存命中回答可以正常渲染 Markdown。
- 命中后 loading 正常结束，停止生成按钮恢复。
- 清空对话不删除 Redis 映射或答案文件。

## 12. 完成定义

满足以下条件后，本计划视为实施完成：

1. Redis Key 是带业务前缀的问题原文，Value 是受控答案目录下的相对文件路径。
2. 首页全部预设问题在启动后可直接命中。
3. 普通问题首次生成后形成“问题 → Redis 文件路径 → Markdown 正文”的完整链路。
4. 流式和非流式接口都支持命中与回填。
5. Redis 故障、文件缺失和非法路径不会导致聊天接口不可用。
6. 自动化测试覆盖核心命中、未命中、写入、降级和路径安全场景。
7. 端到端演示能够清楚呈现第一次慢、第二次快以及预设问题首次即快。
